# แพ็กเกจราคา (Price Plans)

วิชา หลักสูตร และข้อสอบขายแยกตั้งราคาได้หลายแพ็กเกจตามระยะเวลาเรียน เช่น 30 วัน 3,000 บาท, 60 วัน 5,000 บาท หรือแบบไม่จำกัดเวลา การซื้อทุกช่องทาง (เว็บนักเรียนและแอดมินสร้างออเดอร์ให้นักเรียน) ใช้ราคาจากแพ็กเกจ หนังสือยังใช้ราคาเดียวเหมือนเดิม

## ตาราง `price_plans`

| คอลัมน์ | ความหมาย |
|------|------|
| `course_id` / `curriculum_id` / `assessment_id` | เจ้าของแพ็กเกจ มีค่าได้ช่องเดียว (ข้อสอบเฉพาะ `type = primary_exam`) |
| `name` | ชื่อแพ็กเกจ เว้นว่างได้ ระบบแสดงเป็น "30 วัน" หรือ "ไม่จำกัดเวลา" |
| `duration_days` | จำนวนวันที่เรียนได้หลังชำระ `null` = ไม่จำกัดเวลา (1–3650) |
| `price` | ราคาปกติ |
| `sale_price` | ราคาลด ต้องไม่เกิน `price` ถ้ามากกว่า 0 จะเป็นราคาที่ต้องจ่าย |
| `is_active` | เปิดขาย แพ็กเกจที่ปิดไม่แสดงใน API และซื้อไม่ได้ |
| `sort_order` | ลำดับที่แสดง |

แต่ละรายการต้องเปิดขายอย่างน้อย 1 แพ็กเกจ ตั้งได้สูงสุด 10 แพ็กเกจ

คอลัมน์ `price` / `sale_price` เดิมของ `courses`, `curriculums` และ `price` ของ `assessments` ยังอยู่ ระบบตั้งค่าให้เท่ากับแพ็กเกจที่เปิดขายและถูกที่สุดทุกครั้งที่บันทึก ใช้แสดงราคาเริ่มต้นในรายการแอดมินและฟิลด์ `price` / `effective_price` ของ API เดิม

ตอนเพิ่มตาราง (migration `2026_10_17_110000_create_price_plans_table`) ระบบสร้างแพ็กเกจแบบไม่จำกัดเวลาจากราคาเดิมให้ทุกวิชา หลักสูตร และข้อสอบขายแยก สิทธิ์เรียนของรายการเดิมจึงยังเหมือนก่อน

## หน้าแอดมิน

ฟอร์มเพิ่ม/แก้ไขวิชา หลักสูตร และข้อสอบขายแยกมีส่วน **แพ็กเกจราคา** แทนช่องราคาเดิม เพิ่ม ลบ เลื่อนลำดับ และปิดขายได้ หน้ารายละเอียดแสดงรายการแพ็กเกจ หน้ารายการแสดงราคาถูกสุดพร้อมคำว่า "เริ่มต้น · n แพ็กเกจ" เมื่อมีมากกว่าหนึ่งแพ็กเกจ

ลบแพ็กเกจที่เคยขายแล้วได้ ออเดอร์เดิมยังเก็บจำนวนวันและราคาไว้ในรายการออเดอร์ (`order_items.price_plan_id` จะกลายเป็น `null`)

หน้า **นักเรียน → สร้างออเดอร์** ต้องเลือกแพ็กเกจเมื่อรายการนั้นมีหลายแพ็กเกจ ถ้ามีแพ็กเกจเดียวระบบเลือกให้

## การซื้อ

- รายการในตะกร้าส่ง `plan_id` ได้ ถ้าไม่ส่งและรายการมีแพ็กเกจเปิดขายแพ็กเกจเดียว ระบบใช้แพ็กเกจนั้น ถ้ามีหลายแพ็กเกจตอบ `422` "กรุณาเลือกแพ็กเกจราคาของ ..."
- `plan_id` ที่ไม่ใช่ของรายการนั้นหรือปิดขายแล้วตอบ `422`
- `order_items` เก็บ `price_plan_id`, `access_days` (สำเนาจำนวนวัน ณ ตอนซื้อ) และ `metadata.plan_name` ชื่อรายการต่อท้ายด้วยชื่อแพ็กเกจเมื่อเป็นแบบมีวันหมดอายุหรือมีหลายแพ็กเกจ เช่น `วิชาฟิสิกส์ (30 วัน)`
- คูปองคิดจาก `total_price` ของแต่ละรายการเหมือนเดิม

## สิทธิ์เรียนหลังชำระ

ตอนออเดอร์เปลี่ยนเป็นชำระแล้ว (`StudentPurchase::review()` / `pay()`) ระบบตั้ง `enrollments.expires_at` ตามแพ็กเกจ

| กรณี | `expires_at` |
|------|------|
| แพ็กเกจไม่จำกัดเวลา | `null` |
| ซื้อครั้งแรก หรือสิทธิ์เดิมหมดอายุแล้ว | วันนี้ + จำนวนวัน |
| ต่ออายุขณะสิทธิ์เดิมยังใช้ได้ | วันหมดอายุเดิม + จำนวนวัน |
| มีสิทธิ์ไม่จำกัดเวลาอยู่แล้ว | คงเป็น `null` ไม่ถูกลดลง |

หลักสูตรเปิดสิทธิ์วิชาและข้อสอบข้างในด้วยระยะเวลาเดียวกับแพ็กเกจหลักสูตร ถ้าสิทธิ์เดียวกันมาจากหลายรายการในออเดอร์เดียว (เช่นซื้อหลักสูตรพร้อมวิชาที่อยู่ในหลักสูตร) ใช้ระยะเวลาที่ยาวที่สุด ไม่บวกซ้อน

ออเดอร์เก่าก่อนมีแพ็กเกจไม่มี `access_days` จึงเป็นสิทธิ์ไม่จำกัดเวลาเหมือนเดิม การตรวจสิทธิ์ดูวิดีโอ (`LearningController`) และฟิลด์ `purchased` ของ API ดู `expires_at` แล้ว เมื่อหมดอายุนักเรียนซื้อแพ็กเกจใหม่ได้ แอดมินแก้วันหมดอายุเองได้ที่หน้านักเรียนเหมือนเดิม
